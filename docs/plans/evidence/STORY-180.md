# STORY-180 - report artifacts in object storage: evidence and status notes

Owner decision 54 (2026-11-02) answers the story's four open decisions. Built on it:

| Decision | Built as |
|---|---|
| (1) Keep E-0, upload after commit | `ExportService.export` records the row with `object_key = 'pending:<id>'`, presigns locally, and registers the upload with `afterCommit`. The upload (`put`, no transaction open) is followed by ONE short tenant transaction that records the real key. No async job. |
| (2) On-screen link = 15-minute presign, re-presigned on each fetch | `download_url` is the authenticated API route `GET /v1/exports/{id}/download` (`export:data`, cookie session). Each fetch reads the artifact on the AMBIENT request transaction (since round 2; the presign is a local signature taken inside it, ADR-0003 question open) and 302s to `presignGetStored("reports", <stored key>, 900 s)` with `Content-Disposition: attachment; filename="<filename>"`. 409 while the key is `pending:`, the neutral 404 for unknown / expired / other-workspace. `EXPORT_DOWNLOAD_URL_SECONDS` in `contracts/reports/export.schema.ts`. Review round 1 replaced the presign-in-the-export-response, which could be clicked before the post-commit upload landed and could not be refreshed on an Idempotency-Key replay. |
| (3) 7-day emailed link = stored revocable token, then a fresh 15-minute presign | `GET /v1/report-links/{workspaceId}/{token}` (public, tenant-less, 302). Migration 0161 adds `report_artifacts.link_token_hash` (SHA-256, unique where set) and `link_revoked_at`. The link lives until the artifact's own `expires_at` (7 days from build). |
| (4) 8 MB = 8,388,608 bytes | `REPORT_ATTACHMENT_MAX_BYTES`. A file of at most that is attached, one byte more is linked. |

## Design points a reviewer should know
- **The link token is derived, not random:** `HMAC-SHA256(HKDF-SHA256(QUEUE_JOB_SIGNING_KEY, salt empty, info "nominara/report-link", 32 bytes), artifact_id)` (no purpose prefix; the purpose is carried by the HKDF info), base64url (43 chars). A cadence delivery that fails is retried with the SAME artifacts and its email must stay byte-identical (Resend refuses a changed body under one idempotency key); a random token cannot be recovered from the stored hash. Only the SHA-256 is stored. The key is an HKDF subkey (info `nominara/report-link`) of the job-signing key, and the hash is written once: if the signing key rotates between a delivery's attempt and its retry, the plan FAILS CLOSED (delivery fails, is retried, settles failed with a notification) instead of overwriting the hash and killing links already mailed. A dedicated non-rotating `REPORT_LINK_SIGNING_KEY` would close that window; it would be a new environment setting, so it is left to the owner (see Open).
- **The route's workspace id is a lookup scope, not a credential.** It selects whose RLS the two statements run under (system actor). A token presented under another workspace's id finds no row. Every refusal (unknown, wrong workspace, revoked, expired, upload never landed, key outside the workspace prefix) is the same 404.
- **The API origin for the link is `OAUTH_REDIRECT_BASE_URL`** (the only existing setting that names the API's public origin). If a dedicated setting is wanted, that is a one-line change in `mailDepsFromEnv`.
- **Known windows:** (a) a failed upload leaves the row `pending:` (counted `nominara_reports_artifact_uploads_total{outcome="put_failed"}`, logged, download route 409, link route 404, cadence resume rebuilds it); (b) if the put succeeds but recording the key fails, the object exists, the row stays `pending:`, and a cadence retry rebuilds a NEW artifact (new id, new bytes), so a partly-delivered retried email is not byte-identical under its idempotency key. Reusing a `pending:` artifact whose object exists needs a storage `head` outside a transaction in the resume path: follow-up. (c) a presign already issued stays valid for its 15 minutes after revocation or workspace deletion; the NEXT click is refused.
- **Per-email attachment budget:** the files attached to one email add up to at most 8,388,608 bytes (in order); the rest become links. This bounds the message (base64 adds a third; Resend refuses over 40 MB) regardless of how many projects or formats a report has. The story / reference say "attachment <= 8 MB"; this reads it per email, which the owner should confirm.
- **The export keeps a 1-second local presign as its readiness probe** (so unconfigured storage answers 503 before anything is rendered). The SDK may resolve role credentials over HTTP on a credential expiry, so this is a network call risk inside the request transaction that ADR-0003 should either permit explicitly or have the adapter resolve at build time. The emailed-link route presigns after its own short transaction ends; the on-screen download route presigns INSIDE the ambient request transaction (round 2), so the same question applies to it.
- A scheduled email resolves its files once, before the first recipient. A file that never reached storage fails every recipient (nothing is mailed), so the delivery reads `failed` and the cadence path retries.
- Observability: span-shaped log lines `reports.artifact.upload`, `reports.link.resolve`, `reports.scheduled.mail_artifacts` (workspace ID only); metrics `nominara_reports_artifact_uploads_total{outcome}`, `nominara_reports_link_clicks_total{outcome}`, `nominara_reports_mail_artifacts_total{outcome}`.

## Not built (needs an owner decision or another story)
- **RETENTION OF STORED REPORT FILES - OPEN, owner to choose before release.** Ownership per `system-architecture.md` section 8: the reports-prefix purge on workspace erasure is STORY-182 (its AC lists raw, crawl and reports); bucket lifecycle expiry rules are STORY-003. Only a PROJECT hard-delete of report objects is unowned. Findings: Nothing removes an artifact's object from `nominara-reports` when `expires_at` passes, nor when a workspace or project is hard-deleted, and no lifecycle rule exists on the bucket (`docker/localstack/init-buckets.sh` has none; `retention.ts` `deleteObjectPrefix` is unwired and does not cover the reports bucket). Before this story the file bytes were never stored. Choose: (a) a sweep that deletes the object (outside any transaction) then marks the row, also clearing stale `pending:` rows; or (b) an expiry lifecycle rule on the reports bucket of at least 7 days plus a margin, as a stated STORY-003 requirement. Either way, workspace erasure must delete `{env}/{ws}/reports/` (STORY-182); project hard-delete of report objects has no owner. Not built here: it is a new job or an infrastructure requirement, and the choice is the owner's. Until it is made, merging this branch starts storing report bytes that nothing deletes.
- **Revocation has no endpoint.** `link_revoked_at` is honoured on every click; nothing sets it yet. Who may revoke, and from where, is a product question.
- **AC4, the client half, is OPEN, and a HARD MERGE DEPENDENCY: this branch must not merge without the client PR (the story must not read `done` until both land).** Round 4 settled the 409 race by contract: the first request can answer 409 with `Retry-After: 1`, so the client must poll with `fetch` (credentials include, redirect manual) and navigate only once it is not 409. The client work (poll-then-navigate, http(s) demo URLs, rewritten `reports.test.ts` and `methodology-footer.test.tsx`), then rebuild the client dist and `pnpm install --force`, is unbuilt. `app-fnt-dev-main` `components/reports/ReportsSection.tsx` still decodes / anchors `download_url` with the `download` attribute and `lib/demo/routes/reports.ts` still returns `data:` URLs (no longer valid for `z.url({protocol: /^https?$/})`). `download_url` is now the API's own route, so the client must open it with the session cookie (`window.open` or a plain navigation; the server's Content-Disposition names the file, so cross-origin `download` is not needed) and the demo routes must return http(s). This worktree may not touch the client checkout.
- **Dedicated link signing key** (see Design points): an owner decision on a new environment setting.
- **Isolation suite:** no new ISO assertion was added (it would need a registry entry and a breaker). `report_artifacts` is covered by the generic ISO-01/02/03/04/08 for every runtime role, and the cross-workspace token refusal is proved through HTTP under the real `nominara_app` role in `test/integration/report-link-http.spec.ts`.
- **Real buckets (STORY-003)** are not part of this change; LocalStack/dev backend only.

## Review round 2 (fixes)
- Download route: lookup and download_count run on the AMBIENT request client (count under a savepoint); no PG_POOL, no extra checkout. The presign is local but DOES run inside the request transaction (same ADR-0003 question as the export probe, still open). Unit test: 50 concurrent resolves; integration test: 40 concurrent downloads against the default 10-connection pool.

- `recordedArtifacts` carries `workspace_id` on both tables. The orphan delete in `upload` now runs after the pooled client is released.
