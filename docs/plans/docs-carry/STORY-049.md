## Decisions taken (each needs the owner or architect to confirm, or reject)

1. **Provisional page cap of 25** behind `pageCapForPlan` (`page-selection.ts`) until the entitlement key exists.
2. **No pages table.** Per-page outcomes live in `aux_audits.error_summary` (jsonb, `auxErrorSummarySchema`) and in `manifest.json` under `dom_object_prefix`. A pages table is a schema decision (migration pair, isolation entry, RLS) nobody has made; STORY-050/051 may raise it.
3. **"Sanitisation before storage" means text bound for Postgres only** (`sanitise.ts`: NUL bytes and other characters Postgres text cannot hold). The two stored page copies are the bytes AS FETCHED, gzipped, with a sha256 of the uncompressed content, because the render-mode rules compare them and a rewrite would destroy the difference.
4. **Evidence URLs are ranked before sitemap-priority pages** in `key_pages`: owned citations (last 90 days) and open-task URLs first.
5. **"The supplied URL" for an unverified domain is the project's `root_url`**; `payload.targetUrls` is ignored when the domain is not verified, so a job cannot ask for more than ownership was proved.
6. **`pages_failed` counts pages with NO stored copy (plus site-file failures).** A page with a stored plain copy and no rendered one is `partial`, counted in `error_summary.pages_partial`, and still makes the audit `partial`. With no renderer installed `pages_failed` is therefore 0 and `pages_partial` equals `pages_crawled`.
7. **Bounds that are NOT FROM THE REFERENCE** (review round 1; the Crawl-delay clamp was REMOVED in round 4, see the end): `CRAWL_WALL_CLOCK_BUDGET_MS = 10 min` and `IDLE_IN_TRANSACTION_TIMEOUT_MS = 15 min` (`crawl-audit.handler.ts`). robots.txt is untrusted input read even for an unverified project; without the budget `Crawl-delay: 86400` kept one job asleep for days holding a worker slot and an open tenant transaction. The page list is shrunk up front to what fits the budget and recorded: `error_summary.crawl_delay_limited` plus the pages as `crawl_delay_budget` in `skipped_pages` and the manifest's `selection_skipped`. The architect should replace these numbers.
8. **Redirects.** Each hop is vetted before it is requested: off the registrable domain, or into a path NominaraBot's robots rules disallow, is not followed (`redirect_not_followed`). A page that still lands in a disallowed path is discarded (`robots_disallowed_after_redirect`).
9. **Manifest keys are snake_case**, including the probe (`browser_status`, `agent_status`); STORY-051 reads this document.

10. **The differential probe's agent string impersonates OpenAI's crawler verbatim** (`AGENT_PROBE_USER_AGENT`, `differential-probe.ts`: `GPTBot/1.1; +https://openai.com/gptbot`). The reference says only "an AI user agent". Impersonating a named third party's bot is a product and legal choice nobody has signed off, and a site that verifies GPTBot by IP range may block our egress as a fake bot. **Owner sign-off needed**, with an alternative: an AI-agent-shaped string that identifies Nominara (for example `... compatible; NominaraAIProbe/1.0; +https://nominara.com/bot`). That alternative would miss a WAF that matches the literal GPTBot token, which is the very case AUX-R-005 exists to find, so it is a trade-off, not a free swap. The code is unchanged until the owner chooses.
11. **Review round 2 hardening, all NOT FROM THE REFERENCE.** (a) robots.txt matching is a linear-time matcher, not a regex (`robots.ts`): a rule pattern is cut at `MAX_PATTERN_LENGTH = 2048` (a cut Disallow blocks a superset, the fail-closed side) and a path is matched on its first `MAX_MATCH_PATH_LENGTH = 4096` characters (it cannot satisfy a `$` anchor). (b) Sitemap and site-file scanning use `indexOf` (`xml-scan.ts`) and stop at the first unclosed tag, so a hostile file is linear. Both were synchronous and unbounded: a stalled event loop is not interruptible by the wall-clock budget, so the job stalled and was redelivered to the next worker. (c) The probe never follows a redirect (a root redirecting off-site is `inconclusive`, nothing is sent to the third party). (d) `robots_hash` is the sha256 of the raw bytes. (e) A renderer that reports `available: false` is not charged to the politeness budget, and the up-front shrink counts one request per page in that case. (f) A real renderer must charge every guarded subresource request to the `PolitenessBudget` (documented on `Renderer.available`): the reference caps a host at 2 requests per second and a page can make up to `MAX_RENDER_REQUESTS = 100`.
12. **Site-file and sitemap fetches still follow redirects to any public host** (RFC 9309 allows a robots.txt redirect; a sitemap file on another registrable domain is already refused by URL in `collectSitemap`, so a redirect off-site is an inconsistency, not a decision). Whether either may leave the verified site is **an owner decision**: this change vetoes redirects for the probe only.

## OPEN — needs the architect before merge

**The crawl still runs inside one tenant transaction** (KAD-06). Round 1 BOUNDS it (clamp, wall-clock budget, transaction-local `idle_in_transaction_session_timeout`) but does not remove it. Removing it means a fetch phase with no transaction open and a short tenant transaction for the writes, which changes the worker-factory pattern: an architectural decision, not slipped into this story. Record the decision here before merge.

**Status after review round 2: NOT decided, and not decidable in this story.** The two ways out are (a) accept the bounded single-transaction shape for D1 and name a follow-up story with its numbers, or (b) split the work into a fetch phase with no transaction and a short write transaction. (b) cannot be done inside the handler: `createJobProcessor` (`worker-factory.ts`) opens the tenant transaction BEFORE it calls the handler, so the handler has no way to end it. It needs a new processor shape in the factory (for example `prepare(tx)`, then `run()` with no transaction, then `commit(tx)`), signature verification still first, with the `auditId` `ON CONFLICT` idempotency kept. That is a new architectural pattern and needs an ADR in `docs/adr/` (the default answer is no) and the architect's decision on (a) versus (b). Until that is recorded, this branch must not merge. Numbers today: wall-clock budget 10 min, idle-in-transaction backstop 15 min, `crawl` group concurrency 3, so up to 3 pooled connections can each be held for up to 10-15 minutes.

## Review round 4 (carry into STORY-049's technical notes)

- **Crawl-delay is honoured exactly; the 10 s clamp is gone.** `MAX_CRAWL_DELAY_SECONDS` is deleted. aux-and-geo-analysis.md section 1 says the crawl "honours `Crawl-delay`", and a clamp crawled a site that declared more than 10 s faster than it asked. The clamp was also unnecessary for safety: `acquire` throws `PolitenessDeadlineReached` before sleeping when the wait would pass the wall-clock deadline, `affordableRequests()` shrinks the page list up front, and every caller records the refusal. So `Crawl-delay: 86400` returns in bounded virtual time, sleeps for no interval shorter than the declared delay, sends nothing after robots.txt that would breach it, and records the skipped site files and pages (`crawl_delay_budget`). AC7 is Met on this reading. `error_summary.crawl_delay_limited.crawl_delay_ms` now carries the declared interval. Tests: `politeness.test.ts` (declared delay honoured exactly), `page-crawl.test.ts` (hostile delay), `crawl-audit-handler.spec.ts` "REVIEW - a robots.txt with Crawl-delay %s is HONOURED". Consequence for the open transaction: an honoured long delay no longer lengthens the transaction past the 10 min budget (it shortens the crawl instead), so the KAD-06 numbers below are unchanged.
- **AC4 is Partial** (table above): the verbatim-robots requirement is unmet. Fix options for the owner/architect: store the raw robots bytes gzipped under `dom_object_prefix` (an object layout the story did not name), or add a second hash over the stored text and record truncation. Not changed.
- **Site-file origin is the registrable apex (deferred, recorded).** Site files are fetched from `https://{root_domain}` and that one robots.txt is applied to every page on any subdomain. RFC 9309 scopes robots.txt per host, so pages on `www.` or `blog.` are judged by the apex's rules, and if the apex does not serve but `www` does, all four site files fail and the audit ends `failed` even with a valid `root_url`. Fix: derive the site-file origin from `root_url`'s host and fetch or cache robots.txt per host for pages on other subdomains. Deferred: it changes what is fetched and what AC9's authorisation means for a subdomain, which is a story-level decision.
- **KAD-06 blocker: STILL OPEN, no decision recorded.** Round 4 did not resolve it and this branch does not claim to. Choosing between (a) a recorded acceptance of the bounded single-transaction shape for D1 with a named follow-up story, and (b) a `prepare(tx)`, `run()` with no transaction, `commit(tx)` processor shape in `worker-factory.ts` (a new architectural pattern, needing an ADR in `docs/adr/`; the default answer is no) is the architect's, so no ADR was drafted and no test that would fail today was committed. The test that must accompany the fix is already specified: no transaction is open during a fetch, mirroring `KAD-06 - no transaction is open while a domain is being checked` in `domain-reverify-handler.spec.ts`. The branch must not merge until it is decided.
- **Linear-time assertions.** The 5000 ms bounds in `sitemap.test.ts` and `robots.test.ts` now carry a comment citing the measured times of the replaced regex implementations (not finished at 40 s and 20 s), so the bound is visibly still meaningful.

## Review round 5 (carry into STORY-049's technical notes; SUPERSEDES what the banner lists)

**KAD-06 is closed, by ADR-0003 (`docs/adr/ADR-0003-phased-tenant-jobs.md`).**
- `createJobProcessor` accepts a PHASED processor (`phasedProcessor`, `src/lib/queue/worker-factory.ts`): `prepare(tx)` in one short tenant transaction, `run(prepared)` with NO transaction and NO pooled connection, `commit(tx, prepared, fetched)` in a second short tenant transaction. The signature is still verified before any client is acquired, both transactions set the tenant context from the verified payload (`set_config(..., true)`), and a phased processor on a non-tenant queue is refused at construction.
- `crawl.audit` is phased. `prepare` reads the project, the plan, the verification verdict, the evidence URLs, and binds the object store to the workspace. `run` does every fetch, render and object-store write. `commit` claims the audit row (`INSERT ... ON CONFLICT (id) DO NOTHING`, then `FOR UPDATE`; a duplicate that lost the race writes nothing), then writes findings and the final audit row atomically. The audit row is no longer inserted before the crawl, so a failed `run` leaves no orphan `running` row.
- Removed with it: `IDLE_IN_TRANSACTION_TIMEOUT_MS` and the transaction-local `idle_in_transaction_session_timeout` (there is no long transaction to back-stop). `CRAWL_WALL_CLOCK_BUDGET_MS` (10 min, NOT FROM THE REFERENCE) stays: it bounds how long a worker SLOT is held, not a connection.
- Proof: `test/integration/crawl-audit-kad06.spec.ts` (runs through the real `createJobProcessor` as `nominara_app`): no `idle in transaction` backend and no checked-out pooled client during any fetch, render or object-store write (with the counts of each observed, so it is not vacuous); a tampered job acquires no connection; a job signed for workspace A naming workspace B's project fetches and writes nothing; two deliveries racing through `run` write one audit and count each finding once; a failed `run` or a failed commit leaves no row and the retry completes; the default store is bound inside the tenant context and every key lies in the job's workspace prefix. Unit: `test/unit/queue/worker-factory-phased.spec.ts`. Mutation-checked: forcing the factory to ignore phases fails the KAD-06 test; removing the duplicate check in `claimAudit` fails the race test.
- Orphaned objects: a job that exhausts its retries leaves page copies and a manifest under `crawl/{env}/{workspace_id}/{audit_id}/` with no row pointing at them. They are inside the tenant's prefix; a retention sweep by prefix owns them (not built). A retry overwrites them.
- Open for the architect: confirm or reject ADR-0003 (it is a new pattern, adopted on the owner's instruction). `crawl.discover` and `source.verify_presence` also fetch and could adopt it; neither is changed here.

**Crawl-delay is capped at 60 s (replaces round 4's "honoured exactly"; AC7 stays Met).** `MAX_HONOURED_CRAWL_DELAY_MS = 60_000` (`politeness.ts`, NOT FROM THE REFERENCE, owner instruction "cap or schedule").
