## 4. Decisions taken (flagged for the owner)

1. **Owners and admins only (owner decision 2026-10-23, recorded 2026-10-26; review round 3).** RbacGuard gates the route on `tracking:trigger`, and `ReparseGuard` (`src/modules/tracking/reparse.guard.ts`) narrows it by the caller's LIVE role (`req.membership.role`): any role but `owner` and `admin` is a `403` naming `tracking:trigger`, with the message "re-parsing a result is limited to workspace owners and admins"; an API key has no membership and is refused by RbacGuard. This is an explicit role check, not a matrix entry, because a new permission is a change to `security-and-tenancy.md` §6 and `permission-matrix.spec.ts` pins that table at 34 rows. **Docs edit:** in §6 add a note under the `tracking:trigger` row — `POST /results/{id}/reparse` additionally requires the owner or admin role (a scoped manager holds `tracking:trigger` and is refused). Test 034-RT1.
2. **The re-parse reads the STORED RAW OBJECT, before the request transaction opens (review round 3, AC9 / tracking-engine.md §8).** `ReparseGuard` is a route guard, so it runs ahead of `TenantContextInterceptor`: it calls `ReparseService.prefetchSource`, which takes one short tenant transaction (the row's key, the caller's project scope, the retention window), releases the connection, then reads the object with NO transaction and NO pooled client (the `TenantObjectStore.bind()` pattern) and decodes it. The handler's one transaction then re-reads the row `FOR UPDATE`, refuses with `409 conflict` if the key moved in between, and parses and writes. A legacy row with no object is parsed from `payload.text` (no storage read); a row that names an object but arrives with none is refused (a bypassed guard must not read S3 inside the transaction). A missing object is `422 precondition_unmet`; a foreign key is `StorageTenancyError`. Tests 034-AC9n..u. **Known cost:** the guard runs before the idempotency interceptor, so a replayed `Idempotency-Key` still reads the object once; it is an object read, not a parse. A request refused for scope or retention reads nothing.
3. **Citations are not re-fetched.** A re-parse reuses each citation's recorded resolution (status, final URL, `resolved_at`); a URL the improved extractor finds that was never resolved is stored unresolved (`http_status` NULL, excluded from share), exactly like any unresolved citation. Fetching a citation's host from a request handler is what KAD-06 bans.
4. **The dirty mark includes the open day.** `markDateDirtyIfLate` (STORY-042) skips today because every run enqueues its own rollup; a re-parse rewrites today's figures with no run behind it, so `markDateDirty` marks any date.
5. **`capture.parse` now takes a row lock** (`SELECT … FOR UPDATE` on the capture) so a re-parse and a worker parse of one capture cannot interleave their delete-then-insert.
6. **The audit row records the outcome only** (`result_id`, `scoring_version`, `changed`, `credits_charged`), not the diff: the default would store entity labels in the append-only log.
7. **`StorageModule` is imported by `TrackingModule` and `QUEUE_PRODUCER_CONNECTION` is exported** from `QueueProducerModule` (the API's one non-job write to the queue instance is the `rollup_dirty` mark).
8. **Review round 1, still for the owner.** (a) Decision 1 is now the owner's wording (see 1); the route is still unthrottled (each new Idempotency-Key runs a full parse inside the request transaction), so consider a per-workspace limit. (b) Decision 2 now reads the object; record in system-architecture.md §8 that a re-parse reads the raw object through a route guard ahead of the request transaction. The "slim `payload`" follow-up recorded in STORY-181 no longer breaks re-parse for rows that have an object. (c) Known edge, not changed: re-parsing a row still in `captured` before its `capture.parse` commits makes the worker take the L3 short-circuit, so that parse never reaches the alert meters (STORY-037/038/039). It needs a user acting within seconds of capture; the story's test 034-AC9a treats `captured` as re-parseable, so refusing it is a spec decision, not a fix.
