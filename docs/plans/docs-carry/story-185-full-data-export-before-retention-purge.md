A section is in scope when the new window is a number and the replaced one was null (unlimited or not applicable; the deferral record cannot tell those apart) or longer.

CSV cells are formula-defanged. A hand-written ZIP writer over `node:zlib` (`lib/billing/retention-export/zip.ts`): the repository has no zip dependency (only transitive ones behind testcontainers and pdfkit), none was added. No ZIP64: a build over 4 GiB (or 65,535 files) fails `zip_limit` rather than writing a corrupt archive. The zip is held in memory until uploaded (the port's `put` takes a whole body).
- **Coverage** (`coverage` on the row and `manifest.json`): per project, per section, `count` (raw captures; rollup DAYS; attribution DAYS, the notice's units), oldest, newest, the cutoff; `unreadable` raw objects; `complete`. - **Job** `billing.retention_export` (queue added beyond section 4: tenant-scoped, signed, `report` worker group, concurrency 1, ladder doubling(3), key `retexp:{workspace}:{export}`), PHASED (ADR-0003). `prepare` and `commit` are short tenant transactions; reads are paged short transactions through the step hook; raw objects are fetched between pages and the zip is uploaded with no transaction open (tested: no `idle in transaction` backend during an object read, the upload or the email). Each project's export lock (`withExportLock`, EC-40) is held around that project's reads, on a dedicated idle connection: a purge of that project skips (tested with a live `tryPurgeProject`). The row becomes `ready` only after the upload, the email goes only after that commit. Each delivery uploads under its own run id; the `ready` write is conditional, so a duplicate delivery neither overwrites nor mails twice.

The last failed attempt marks the row `failed` (`build_failed` / `prepare_failed`, `deferral_ended`, `zip_limit`); the owner can request again.

Fix round (audit; migration **0206**, expand-only):
- **Superseded exports (major).** `retention_exports.scope jsonb` = `{ purge_not_before, raw_cutoff, rollups_cutoff }` the export was built for (set at request, rewritten by the job's prepare from the scope it actually reads). `request()` reuses a ready or in-flight row only when its scope EQUALS the current `readExportScope`; otherwise a ready row is superseded and an in-flight one is failed `superseded`, and a new build starts. A legacy row (null scope) never matches. The retention notice links an export only when it matches the scope the change itself leaves in force (`scopeFromParts` over the planned deferral), so a shortening that moves the cutoffs never links an export it just made incomplete. **Contract:** `status` gains `superseded` (a ready, unexpired export built for an earlier scope: `download_url` null, not complete; POST builds a new one).
- **Orphaned objects (major).** The object key is now deterministic per export id (`retention-exports/{id}.zip`): a retry or duplicate delivery overwrites it. A lost race deletes its own upload unless the row is ready. The nightly cleanup now deletes the object of ANY expired export whatever its status (ready rows by their stored key, others by the derived key), tolerating a missing object, and stamps `object_purged_at`.
- **Memory (major).** A byte budget (`RETENTION_EXPORT_MAX_BYTES` = 1 GiB, PROVISIONAL, for the owner to confirm) counts raw bytes (answers and both CSVs) as they are read; over it the build fails fast with `ZipLimitError` -> `zip_limit` before reading the rest. Rows and answers are encoded once into Buffers and concatenated once; the zip deflates per entry. Follow-up (not built): stream the archive to a multipart upload, which removes the cap.
- Minors: the download presign lives min(15 min, time left); an expired in-flight row is failed `expired` before the insert (same transaction); the ready email goes only while the requester is still an active owner or admin (the export still becomes ready); the prepare UPDATE carries `workspace_id`. Follow-ups, not built: a cool-down after repeated failures; confirm the worker pool's DSN bypasses pgBouncer for the session advisory lock.
